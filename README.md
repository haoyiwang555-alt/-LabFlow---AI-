### 2. 开题报告正文复制内容

#### 选项 A：投递「晶泰科技」开题报告
*   **Part 1 · 命题前置分析与洞察**（建议 50-300 字）：
    > 晶泰智能自主实验室的核心矛盾不是缺少会议记录，而是研发信息无法围绕“实验对象”连续流动：参数、争议、风险、决策和失败原因散落在转写、文档、表格及个人经验中，导致决策依据难追溯、会后任务与实验脱节、相似错误重复发生。普通 AI 纪要只能压缩文本，不能保证知识可执行、可验证、可复用。我们因此把目标定义为“24 小时知识 SLA”：会议结束 24 小时内，经过确认的关键结论必须带证据时间戳、实验编号、适用边界和责任人，能被有权限的团队成员检索、理解并在下一次相似实验中主动触发。
*   **Part 2 · 整体解决方案设计**（建议 300-600 字）：
    > 我们拟开发“晶流 LabFlow”AI 实验研发加速器，以实验编号为主线打通“方案研讨—参数评审—实验执行—结果复盘—知识沉淀—经验复用”。会前，系统聚合当前实验参数、历史决策、未关闭风险和相似成功/失败案例，生成研发上下文包；会中，基于飞书会议 AI 转写，以领域 Structured Output 识别参数、假设、方案争议、风险、决策与行动项，每条结论保留说话人、原文时间戳、置信度和适用边界；会后，负责人审核确认后，系统将行动项同步至多维表格，将结论写入文档和知识库，并更新实验状态。知识层采用 pgvector 语义召回与 Neo4j 关系图谱结合，既发现相似实验，也校验版本、参数关系、权限和证据来源；失败经验按“触发参数—症状—可能根因—避免策略”单独建模，在下一次实验开始前由风险守门员主动提醒。工程上通过幂等键、消息队列、Checkpoint、多模型降级、权限继承与审计保证可靠和安全。首阶段使用 5-10 场脱敏会议验证结论准确率、证据可追溯率、行动项完整率、24 小时知识 SLA 和知识复用采纳率。我们已完成可运行验证版，包含研发总览、会议解析、实验流转、知识湖、AI 助理、统一检索和任务闭环。

#### 选项 B：投递「健康元药业」开题报告
*   **Part 1 · 命题前置分析与洞察**（建议 50-300 字）：
    > 临床试验开发的核心痛点在于临床方案设计与数据监查的重度依赖人工、反馈滞后。研发会议中的核心方案决策、患者招募异常指标、临床监查风控点往往停留在口头讨论或海量文档中，无法转化为标准化可沉淀的研发知识资产，导致相似设计缺陷和数据合规风险重复发生。通用 AI 助手缺乏临床专业 Schema 约束。我们把目标定义为“24 小时临床数据 SLA”：临床研发研讨或方案评审会后 24 小时内，经过专家审核的试验参数决策、风控点与待办任务，必须带证据链与时间戳，自动写入团队知识湖与飞书多维表，在下一次相似方案设计前主动触发风控。
*   **Part 2 · 整体解决方案设计**（建议 300-600 字）：
    > We拟开发“健流 ClinFlow”AI 临床研发协同加速器。会前，系统自动召回历史相似临床方案与已归档的数据监查合规风险；会中，基于飞书会议 AI，利用针对临床领域优化的大模型 Structured Output 智能识别方案决策（如剂量组设计）、异常指标争议、试验数据风险及行动项，并保留发言人与原文时间戳；会后，通过人机协同审核，系统自动将临床行动项写入多维表并通知负责人，将合规风控模型写入知识库与临床关系图谱。检索层使用 pgvector 向量检索历史方案，并利用 Neo4j 图谱进行方案间的指标映射与合规关联；对于监查失败案例，按“试验阶段-给药参数-毒副反应症状-规避策略”单独建模，形成自动化“风控守门员”，在后续方案进入下一阶段时主动预警。我们已开发本地运行验证版，实现了临床总览、方案解析、风控守门员、ClinFlow 图谱与任务追踪的完整闭环。

## 🎬 四、关于自动生成的演示视频

项目内提供了一个全自动生成的演示视频：**[output/晶流LabFlow-系统演示视频.mp4](file:///M:/%E9%A1%B9%E7%9B%AE/%E6%AF%94%E8%B5%9B/AI%E5%85%88%E9%94%8B%E6%9C%AA%E6%9D%A5%E4%BA%BA%E6%89%8D%E5%A4%A7%E8%B5%9B/output/%E6%99%B6%E6%B5%81LabFlow-%E7%B3%BB%E7%BB%9F%E6%BC%94%E7%A4%BA%E8%A7%86%E9%A2%91.mp4)**。

该视频是通过本地开发工具链全自动合成的，其背后的自动生成逻辑如下：
1.  **语音合成 (TTS)**：执行 `generate_video.js` 会通过 Node 自动在本地拼装具有 UTF-16 LE BOM 编码的 PowerShell 脚本，调用 Windows 原生 Speech 库下的 **`Microsoft Huihui Desktop`** 中文语音，将配音逐句合成为 WAV 音频段，并利用 Node 计算每个音频段的精确毫秒时长。
2.  **画面自动录制 (Playwright)**：启动本地 API 服务器，由 Playwright 驱动 Chromium 浏览器，按照旁白段的时长进行精准的延时和页面自动操作（研发总览 -> 会议结构化解析 -> 知识湖图谱关联 -> 失败风险检索 -> 板块快速浏览），并依靠浏览器内置编码器将其捕获为 WebM 高清视频。
3.  **音视频合并 (FFmpeg)**：视频录制结束后，通过 `ffmpeg` 将所有的分段旁白音频物理拼接，再与浏览器录制轨压制成标准的 `H.264/AAC` 兼容性 MP4 视频，确保在任意播放器上均能音画完美同步。

若需重新生成，可在根目录下在 PowerShell 中执行：
```powershell
node scripts/generate_video.js
```
