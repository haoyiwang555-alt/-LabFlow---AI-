# 05｜路演脚本、演示分镜与答辩问答

## 一、90 秒电梯陈述

大家好，我们是【队名待填】，作品是“晶流 LabFlow”。

晶泰科技的智能自主实验室每天会产生大量实验参数、方案争议、失败经验和优化结论。真正的损失往往不是没有开会，而是开完以后：决策依据散在转写里、行动项与实验脱节、失败经验没有进入下一次实验。

所以我们没有再做一个会议总结工具，而是提出一个可量化的目标：**会议结束 24 小时内，关键结论必须变成全团队可检索、可理解、可复用的知识资产。**

晶流以实验编号为主线。会前自动召回相似实验和未关闭风险；会中用飞书会议 AI 识别参数、争议、风险、决策，并保留原文时间戳；会后将行动项写入多维表，把确认后的结论写入知识库和研发知识图谱。下一次相似实验开始时，历史成功与失败经验会主动出现。

我们的差异有三点：实验对象驱动，而不是会议文件驱动；成功和失败双资产；所有 AI 结论都带证据、置信度和人审状态。现在我们已经完成可运行 Demo，下一步将用 5-10 场脱敏会议验证结论准确率、知识 SLA 和复用采纳率。

## 二、5 分钟完整路演脚本

### 0:00-0:35｜真实问题

**画面：封面/首页英雄区。**

“一个智能自主实验室，真正昂贵的不是一次会议，而是同一个问题被第二次讨论、同一个错误被第二次重复。会议里明明已经说清了参数和风险，但下一位实验工程师找不到，下一次实验也不会主动提醒。”

“我们把命题的核心从‘会议提效’重新定义为‘研发经验的流动速度’。”

### 0:35-1:05｜核心主张

**画面：首页 24h SLA、实验闭环。**

“晶流 LabFlow 是面向智能自主实验室的 AI 研发操作系统。我们的 North Star Metric 是 24h 知识 SLA：会议结束后 24 小时内，经过确认的关键结论能被团队搜索、理解、引用和回溯。”

“它贯穿方案研讨、参数评审、实验执行、结果复盘和知识复用五个阶段。”

### 1:05-2:25｜主 Demo

**操作：点击‘打开 AI 会议解析器’ → 选择 B-17 → 开始结构化解析。**

“现在 B-17 晶型筛选刚开完参数评审会。普通纪要会给我们一段总结；晶流把它拆成研发可执行对象。”

“第一条是方案决策：B-17-03 采用低温梯度进入小试；第二条是风险：高浓度溶剂比例可能造成晶型漂移；第三条不是会议里直接给出的，而是知识关联：系统命中历史 B-11 方案，预计减少 1.5 天试错。”

“每一条都带原文时间戳和置信度，不让 AI 生成不可追溯的‘正确废话’。下方行动项带负责人、截止时间和来源，确认后写入知识湖并同步多维表。”

### 2:25-3:20｜知识复用

**操作：关闭弹窗 → 知识湖。**

“知识湖以实验为中心，而不是以文件夹为中心。B-17 连接到 B-11 历史方案、A-09 失败案例、SOP-17 和 mt-2407 会议证据。”

**操作：顶部搜索‘湿度’。**

“尤其重要的是失败经验。我们把失败模式、触发参数、可能根因和适用边界单独建模。下一次相似实验开始前，风险守门员会主动提醒，而不是等人再去搜。”

### 3:20-4:15｜技术与可信

**画面：AI 助理和运行日志/架构图。**

“后端采用事件驱动的 Agent 流程：会议解析、领域质检、知识关联、任务分派、人审写入。语义召回使用 pgvector，关系与证据使用 Neo4j。每个阶段有 Checkpoint，重复事件由幂等键处理，模型超时自动降级。”

“在安全上继承飞书权限，向量检索也不能绕过 ACL；会议文本视为不可信输入，工具调用白名单；所有结论支持撤回、重审和审计。”

“当前 Demo 的接口、状态、检索和任务是真实实现；由于没有企业账号和数据授权，飞书连接器使用正式契约加脱敏适配器，不伪造真实生产接入。”

### 4:15-5:00｜价值与验证

**画面：首页指标卡/验证表。**

“我们会用 5-10 场脱敏会议验证四类指标：结论 Precision/Recall，证据时间戳可追溯率，行动项闭环率，24h 知识 SLA 与推荐采纳率。”

“目标是让重复讨论时长下降 30%，24h SLA 达标率达到 90%。这些是验证目标，不是未经验证的生产成绩。”

“晶流不替代科研人员判断，它让每一次判断留下证据，让每一次失败都成为下一次发现的捷径。谢谢。”

## 四、常见答辩问答

### Q1：这和飞书妙记/普通会议总结有什么区别？

普通总结的输出单位是文档；晶流的输出单位是带实验编号、参数、证据、适用边界和审核状态的研发知识对象。它还会推进实验状态、同步任务、连接历史成功/失败案例，并在下一次实验前主动召回。

### Q2：没有生物医药背景，如何保证准确？

命题明确不要求深度生物背景。我们不让通用模型直接做科学判断，而是让模型执行“信息提取与关联”：领域 Schema 由企业教练共创；结论带原文；高风险条目必须人审；准确性通过双人标注的 Precision/Recall 验证。

### Q3：AI 幻觉怎么处理？

四道防线：Structured Output + Schema 校验；每条结论必须有原文证据；参数规则/知识图谱做冲突检查；低置信度和高风险结论必须人工确认。系统不允许无证据内容直接写入正式知识库。

### Q4：为什么同时用 pgvector 和 Neo4j？

pgvector 找“语义相似”，Neo4j判断“关系是否成立、版本和权限是否一致、证据从哪里来”。先向量召回，再用图谱关系和参数重叠 Rerank，可以兼顾召回率和可信度。

### Q5：如何接入飞书？

会议结束事件进入 connector-service；拉取有权限的转写与妙记；解析结果先进入人审文档；行动项写入多维表/任务；确认结论写入知识库并保存回链。使用 tenant、resource、permission 标签保证权限继承。

### Q6：数据安全怎么保证？

最小权限、身份透传、字段级脱敏、向量 ACL、模型调用策略、审计日志和可删除机制。会议转写视为不可信数据，不接受其中指令；工具调用只允许白名单参数。演示环境不包含真实企业数据。

### Q7：你们现在完成到什么程度？

已完成可运行产品验证版：真实后端 API、前端 6 个工作台、会议解析主链路、任务创建、统一检索、脱敏数据和素材。未完成的是需要企业账号/授权的真实飞书 API 和真实实验数据验证，这部分会在入围后与企业教练推进。

### Q8：42 小时节省、87% SLA 是真实结果吗？

不是生产成绩，是演示数据，用于说明指标设计。答辩和材料中会明确区分“演示数据”“验证目标”和“真实测量结果”。只有完成样本验证后才更新为实测值。

### Q9：为什么不直接做一个大模型聊天机器人？

聊天机器人依赖人主动提问，无法保证任务闭环和知识沉淀。研发场景需要状态机、权限、证据、版本、审计和主动风险守门，核心是后端流程系统，不是聊天 UI。

### Q10：如何量化商业价值？

按研发人时和实验机会成本估算：减少会后整理时间、重复讨论时间、重复试错批次和跨团队等待时间。试点阶段只展示可观测指标；有真实数据后再换算节省人时与实验成本，避免夸大 ROI。

### Q11：系统会不会增加审核负担？

采用风险分层：低风险、字段完整、证据充分的内容批量确认；高风险参数和冲突内容逐条确认。系统记录用户修改，持续优化 Schema 与提示词，目标是让审核从“重新整理”变成“快速确认”。

### Q12：两人团队如何完成？

先做单一黄金主链路：会议结束 → 结构化结论 → 人审 → 多维表任务 → 知识检索。现有 Demo 已覆盖主链路；入围后再按企业反馈补连接器和评测，不同时铺开所有微服务。

## 五、现场故障预案

1. 浏览器无法联网：项目所有图片已本地化，Node 服务离线可运行。
2. AI 接口超时：演示适配器返回固定可追溯结果，现场不依赖外部模型。
3. 页面加载失败：准备 8 张流程截图和 60 秒录屏。
4. 后端端口冲突：`$env:PORT=5178; npm start`。
5. 飞书账号无权限：使用脱敏样本，不进行现场真实企业账号授权。
6. 时间不足：跳过实验流转，保留“解析器—知识湖—指标”三段。
