# 02｜开题报告（可直接提交）

## 项目名称

**晶流 LabFlow：面向智能自主实验室的 AI 实验研发加速器**

## 项目摘要（约 300 字）

晶泰科技智能自主实验室每天并行运行大量高通量实验，研发会议中持续产生实验参数、方案争议、风险判断、失败原因和优化结论。然而这些高价值信息常被分散在会议转写、聊天、文档和个人经验中，导致决策依据难追溯、行动项难闭环、失败经验难复用。晶流 LabFlow 以“24 小时知识 SLA”为目标，把飞书会议 AI 从会议总结工具升级为研发知识流转中枢：会前聚合同一实验的历史结论与风险；会中识别参数、争议、决策及证据时间戳；会后自动拆解任务并联动飞书文档、知识库、多维表格，同时将成功参数和失败模式写入可检索的研发知识图谱。下一次相似实验开始前，系统主动推荐适用经验与边界。作品将交付可运行 Demo、流程原型、后端接口与脱敏验证数据，重点验证结论结构化准确率、行动项闭环率、历史知识复用率以及从会议结束到团队可检索的耗时。

## 一、背景与问题定义

智能自主实验室的难点不仅是“做更多实验”，更是让多角色在高并发实验中共享准确上下文。当前流程存在四类断点：

1. **信息断点**：实验参数、方案争议和决策依据混杂在会议转写中，难以按实验对象检索。
2. **执行断点**：会议结论到任务分派依赖人工，负责人、截止时间和实验批次容易脱节。
3. **知识断点**：成功参数容易沉淀，失败案例常被忽略，导致相似错误反复发生。
4. **可信断点**：普通大模型总结缺少时间戳、证据来源、置信度与人审状态，不符合研发严谨性。

我们将问题重新定义为：**如何构建一条可信的“会议—决策—实验—结果—知识—复用”链路，让一次实验经验在 24 小时内成为团队资产，并在下一次相似实验开始前主动出现？**

## 二、目标用户

- 研发负责人：需要看全局实验进度、风险与决策闭环。
- 实验工程师：需要准确获得参数调整和下一步执行要求。
- AI/算法工程师：需要数据质量、失败原因和模型反馈上下文。
- 物料与自动化运维：需要把会议行动项与排程、物料状态同步。
- 研发效能负责人：需要量化知识沉淀和复用效果。

## 三、解决方案

### 1. 会前：研发上下文包

输入会议关联的实验编号，自动聚合实验目标、当前参数、历史决策、未关闭风险、相似成功/失败案例，生成会前一页纸，减少重复同步。

### 2. 会中：可追溯 AI 研讨中枢

基于飞书会议 AI 转写，以领域 Schema 识别“参数、争议、假设、风险、决策、行动项”，每条结论保留原文时间戳、说话人、置信度和适用实验，支持点击回听与人工确认。

### 3. 会后：实验闭环编排

将确认后的结论写入飞书文档和知识库，将行动项同步至多维表格，按“方案研讨—参数评审—实验执行—结果复盘—知识复用”状态机推进；异常任务自动提醒并可断点续跑。

### 4. 知识湖：成功与失败双资产

用知识图谱表达实验、参数、样本、人员、会议、结论、风险之间的关系；用向量检索召回语义相似实验，再经过 Rerank 与规则校验，输出“为什么可复用、适用边界、原始证据”。

### 5. 风险守门员

在实验进入下一阶段前检查关键参数缺失、未关闭高风险、结论冲突和权限不一致；若不满足条件则阻断或要求负责人确认。

## 四、创新点

1. 从“会议纪要”升级为“实验对象驱动的研发知识流”。
2. 提出可量化的“24 小时知识 SLA”，直接衡量沉淀效率。
3. 对失败经验进行结构化建模，形成可主动触发的“失败模式库”。
4. 所有 AI 结论都带证据时间戳、置信度、版本和人审状态。
5. 语义检索、知识图谱和实验状态机结合，既能找到相似内容，也能约束业务流程。
6. 将可靠性工程引入 Agent：幂等、事件溯源、Checkpoint、多模型降级和权限继承。

## 五、技术路线

- 前端：React/Vue + TypeScript（当前验证版为零依赖响应式 Web）。
- 核心后端：Spring Boot 3、Spring AI、SSE、Redis、RabbitMQ。
- 数据层：PostgreSQL + pgvector、Neo4j、对象存储、审计日志。
- Agent 编排：会议解析 Agent → 领域质检 Agent → 知识关联 Agent → 任务分派 Agent → 人审节点。
- 飞书连接：会议 AI、文档、知识库、多维表格、任务与机器人消息。
- 安全：飞书身份与权限继承、字段级脱敏、最小权限、全链路审计、可删除与可追溯。

## 六、验证方案与指标

使用 5-10 场脱敏研发会议或构造会议样本，邀请至少 2 名评审者人工标注，采用以下指标：

| 指标 | 定义 | 首阶段目标 |
|---|---|---:|
| 关键结论准确率 | AI 结论中被人工确认正确的比例 | ≥ 90% |
| 关键结论召回率 | 人工标注结论被 AI 找到的比例 | ≥ 85% |
| 行动项字段完整率 | 负责人、截止时间、来源、实验编号完整 | ≥ 95% |
| 证据可追溯率 | 结论可回到原文时间戳 | 100% |
| 24h 知识 SLA 达标率 | 会议结束 24h 内可被团队检索 | ≥ 90% |
| 相似实验复用采纳率 | 推荐知识被负责人采纳 | ≥ 60% |
| 重复讨论时长下降 | 相比无系统流程 | 目标 30% |

以上均为验证目标，不表述为已取得的生产结果。

## 七、实施计划

- 第 1 周：与企业教练确认流程、字段、权限与成功标准，补充 5 场脱敏样本。
- 第 2 周：打通会议转写 → Structured Output → 人审 → 文档/多维表。
- 第 3 周：完成知识图谱、向量检索、失败模式库和风险守门员。
- 第 4 周：小样本评测、异常链路测试、界面与演示脚本打磨。
- 半决赛阶段：接入企业允许的真实流程，进行 A/B 对比与指标复盘。
