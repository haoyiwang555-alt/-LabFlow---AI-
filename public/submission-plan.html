命题场景描述、问题描述及痛点说明

What & Why

真实业务场景

晶泰科技智能自主实验室每天产生大量实验数据、会议讨论和研发决策，但这些信息分散在不同的系统、文档和个人笔记中。研发人员既要处理实验，又要从海量历史资料中查找经验，导致知识难以流动、经验难以复用、错误容易重复。

我们把研发知识流转的完整链条概括为：会前上下文准备 → 会中实时解析 → 会后知识沉淀。在实际研发中，这一链条往往断裂，正是痛点所在。

五大核心痛点

痛点现状对业务的实际影响
知识孤岛会议结论散落在转写、文档、个人笔记中知识检索效率低，想找历史结论要翻多个系统
经验断层新人无法快速了解历史失败案例重复踩坑，失败成本重复发生
任务脱节会议 Action Items 靠人工跟进任务闭环率低，决策落地慢
风险滞后问题暴露时往往已造成损失风险发现滞后，无法提前干预
决策不可追溯不知道某个结论是怎么来的争议频发，难以复盘与归因

技术架构创新：多 Agent 协同流水线

会议转写文本→ MeetingParser Agent→ QualityCheck Agent→ GraphLinker Agent→ Human-in-the-Loop 审核→ 飞书多维表 + Neo4j 持久化

职责分离避免单一大模型的"全能陷阱"；基于 Checkpoint 可中断续跑；主模型超时自动降级至备选模型，保证系统可用性。

具体方案说明（突出 AI 能力）

How

双资产知识模型：让"踩过的坑"成为可触发资产

传统知识管理只沉淀成功经验，晶流 LabFlow 将失败案例建模为同等重要的资产，并构建失败模式库：触发参数、症状描述、根因分析、规避策略、关联实验。当新实验进入"参数评审"阶段，系统自动检测相似失败模式并主动推送风险预警，而非等待人工搜索。

失败模式库→ 触发参数（温度≥28°C / 湿度波动>15%）→ 症状（结晶异常，产率下降23%）→ 根因（环境数据缺失）→ 规避策略 + 关联实验

Canvas 动态知识图谱

区别于静态树状图，采用 Canvas 力导向图展示实验与知识的关联：物理模拟自动布局、悬停高亮关联边、拖拽调整、点击查看详情；节点类型用颜色区分（实验=绿、结论=紫、风险=红），60fps 流畅渲染数百节点。

SSE 流式解析体验

用户点击"开始解析"后，不再等待 5 秒空白，而是看到 Agent 逐步执行：连接飞书会议 AI 转写 → 识别参会者 → MeetingParser 提取参数/争议/决策 → QualityCheck 校验 Schema 与置信度 → GraphLinker 关联图谱与历史实验 → 生成结构化结论与行动项。
